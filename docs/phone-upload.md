# 手机局域网采集与上传

电脑接收原视频并自动处理，手机不运行重建算法。视频通过同一热点／Wi-Fi 直传到电脑，不经过云端中转；选择 Meshy 时，电脑随后发送选出的物体图片给 Meshy。

## 启动和使用

异常批次可由独立的 `scripts/reprocess_phone_jobs.py` 执行固定补处理计划。它通过 SQLite 领取已结束的任务，优先重做失败／待核验项目，与网页正在处理的物体使用不同目录；不会另建 `Intake` 实例或重置主队列。旧模型、场景和报告备份在各任务的 `recovery-history/`，补处理日志为 `recovery-worker.log`。计划及每件完成状态记录在补处理目录的 `plan.json`。

补处理进程与主队列共用一张 GPU，最多各运行一件，不等于算力翻倍。已有 Meshy 结果复用；从未生成过模型的任务首次请求仍会消耗 API 积分。真正的杯碗内腔继续使用 local，封盖杯面可通过逐物体 `geometry: outer_shape` 设置纠正名称推断。保存在任务目录的 `recovery-settings.json` 会用于后续网页重试。

在项目目录运行：

```bash
./run-upload.sh
```

脚本检测常见 Linux 热点地址 `10.42.0.1`，存在时监听该热点；否则只监听本机，可显式指定电脑的局域网地址：

```bash
./run-upload.sh --host 192.168.1.100 --port 8765
```

终端会打印网页地址、8 位配对码和保存目录。手机连接这个电脑热点／同一个路由器 Wi-Fi，打开该地址并输入配对码。不要填写 Meshy API key；API key 继续由电脑端配置读取，网页不接收也不发送它。

1. 点击“直接拍摄”或“选择已有视频”。一个视频对应一件物体。
2. 填物体名称，默认取视频文件名。选择 Meshy 或 local，可选 Blender 展示。
3. 点击“上传并自动生成”，显示百分比、实测速率和剩余时间。
4. 看到“电脑已接收”后可关闭网页或继续拍下一件。电脑按上传完成后的队列逐件处理。
5. 队列中可查看阶段、下载 OBJ、结果 ZIP，以及请求生成的 Blender 文件。Meshy 尺寸校正通过时还会出现 `_dimensions.obj`，原 OBJ 保留。已有同视频的本地完成任务会自动作为尺寸参考；没有时用照片约束。

Meshy 默认选“本地尺寸混合”：一次上传，共用相机、A4 定标和可用深度缓存，自动补齐本地尺寸参考，再校正 Meshy。无需先单独跑一个本地任务；本地计算不消耗 API 积分，但首次需要深度计算时间。也可选择“快速照片校正”，不主动补建本地模型；该模式若缺少稀疏特征仍会补算深度定位。两种模式都不默认做平滑。点击上传并自动生成会使用已经配置的 Meshy API 积分。形状检查不达标但成功导出的模型标为“模型已保留 · 待核验”。失败后“复用缓存重试”沿用原任务目录和 API 任务号；结果不明的 API 提交不会被自动再次付费提交。

## 上传速度与拍摄兼容性

上传速度取决于手机与电脑之间的无线连接和文件大小，不取决于互联网的上传带宽。页面实时显示实际 MB/s；例如一个 100 MB 视频，若实测 5 MB/s，纯传输约 20 秒，这只是按速度计算的示例。电脑仍需互联网访问 Meshy。

建议使用 1080p / 30 fps，避免无必要的 4K、慢动作或很长的视频。原视频保持原样传输，不在浏览器额外转码，以避免手机发热、等待以及压缩损失。电脑按需要选帧。

“直接拍摄”使用文件输入的 `capture="environment"`，尝试调用手机系统相机；相机分辨率由系统／浏览器决定，网页不能保证强制 1080p。[MDN capture 文档](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture)。某些浏览器只显示文件选择器，此时先用系统相机录制再选视频即可。普通局域网 HTTP 不能依赖网页内 `getUserMedia` 实时摄像头，因此此版本没有自制实时取景器。[MDN 安全上下文要求](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。

上传期间保持网页在前台和屏幕亮起；手机系统可能暂停后台网页。分块大小 4 MiB，中断后再次点击上传或在队列中选择原视频续传。重连时核对已上传前缀，已确认的分块不会重复追加。不要清除浏览器存储；清除后仍可从队列选择对应物体续传。

当前单文件上限 2 GiB。接收完成后检查视频元数据并记录完整 SHA256，再进入生成队列。验证过 1920×1080、约 57 MB 的 HEVC MOV/MP4 类视频接收和哈希一致；电脑本机的吞吐测试不能代表手机 Wi-Fi 速度。手机浏览器可能无法预览某种 HEVC 文件，但电脑仍可接收和解码。

## 文件和服务管理

默认数据目录 `phone-workspace/` 已从源码发布中排除：

```text
phone-workspace/
  access-code.txt              # 本机配对码（不是 Meshy API key）
  queue.sqlite3                # 队列与续传状态
  jobs/<任务ID>/
    input/<物体名>.mp4         # 完整接收的原视频，后缀沿用输入
    output/models/<物体名>/   # 最终 OBJ 与状态
    output/scene-package.zip
    worker.log
```

同名物体使用不同任务目录，不覆盖旧结果。服务重启后未完成生成会复用已有缓存继续排队；上传中断保留 `.part` 文件供续传。电脑关机期间不能接收，重启后须重新启动服务。终端启动时按 Ctrl+C 停止；网页关闭不会停止电脑生成。

本次安装若由 systemd 用户服务启动，可查看或停止：

```bash
systemctl --user status packing-assets-upload
systemctl --user stop packing-assets-upload
```

这是当前登录会话中的临时服务，不自动设置开机启动。停止后可在项目目录重新运行 `./run-upload.sh`。

仅需要接收视频、不启动生成时：

```bash
./run-upload.sh --upload-only
```

这是一套私有局域网工具，绑定电脑热点／指定内网地址，不做公网映射。配对码仅分享给需要上传的设备；页面只提供已导出的模型文件，不提供视频、日志、用户配置或 API 凭据的下载接口。
